===============================================================================
 MY QUICK YUMMY - REQUIREMENTS
===============================================================================
 Everything needed to run this project, and every package it depends on.

 This is a Node/JavaScript project, so dependencies are installed with npm from
 the package.json files listed below - not from this file. This document is the
 human-readable manifest: what to install, what version, and why.

   Install:   cd mernapp/backend && npm install
              cd mernapp          && npm install
   Seed:      cd mernapp/backend && npm run seed
   Run:       cd mernapp/backend && npm run dev     (API,        :5000)
              cd mernapp          && npm start      (storefront,  :3000)

 4. ENVIRONMENT VARIABLES
-------------------------------------------------------------------------------

  mernapp/backend/.env           (git-ignored; template at .env.example)
  ---------------------------------------------------------------------------
  PORT                   no    default 5000
  NODE_ENV               no    default development
  CORS_ORIGIN            no    default http://localhost:3000; comma separated
  MONGO_URI              YES   MongoDB connection string
  JWT_SECRET             YES   Signs customer tokens
  JWT_EXPIRES_IN         no    default 7d
  ADMIN_EMAIL            YES   Admin console login id
  ADMIN_PASSWORD         YES   Admin console password
  ADMIN_JWT_SECRET       YES   Signs admin tokens - MUST differ from JWT_SECRET
  ADMIN_JWT_EXPIRES_IN   no    default 12h

  The server validates these at boot (backend/config/env.js) and refuses to
  start if a required one is missing, so a misconfigured deployment fails
  loudly instead of running without authentication. It also refuses to start if
  JWT_SECRET and ADMIN_JWT_SECRET are equal, or if either is shorter than 32
  characters - a shared or guessable signing key would let a customer token
  authenticate as an admin, which is the whole point of keeping two.

  mernapp/.env                   (git-ignored; template at .env.example)
  ---------------------------------------------------------------------------
  REACT_APP_API_URL      no    default http://localhost:5000

  Create React App inlines REACT_APP_* at BUILD time and exposes them to the
  browser. Never put a secret in the frontend .env.


-------------------------------------------------------------------------------
 5. DATABASE
-------------------------------------------------------------------------------

  Database name: myqymern (or whatever MONGO_URI points at)

  Collections
  ---------------------------------------------------------------------------
  users           customer accounts (bcrypt password hashes)
  orders          legacy nested-array order history, kept for compatibility
  receipts        billing + delivery record per checkout; drives the PDF,
                  the live tracker and the admin receipts screen
  partners        restaurants, hotels, cloud kitchens, food stalls, bakeries
  food_items      the menu
  foodCategory    the categories customers browse first
  riders          the delivery fleet and its live status
  policies        rider/partner/customer policies, internal SOPs, legal pages
  faqs            the FAQ accordion

  Seed data lives in mernapp/backend/seed/data/ and is applied by
  `npm run seed`. The seed is idempotent - re-running it produces identical
  values - and never touches the users or receipts collections.

 7. ONE-TIME REPOSITORY SETUP
-------------------------------------------------------------------------------

  Enable the secret-scanning pre-commit hook (once per clone):

      git config core.hooksPath .githooks

  It refuses a commit that adds a .env file, either of the two credentials this
  repo previously leaked OR A FRAGMENT OF ONE, a MongoDB URI with inline
  credentials, or a secret-shaped variable assigned a literal. Placeholders in
  .env.example and documentation are exempt.
  Deliberate override: git commit --no-verify

  Matching by prefix is deliberate: a partial copy of a secret is still a leak.

  Related: scripts/purge-secrets-from-history.sh redacts committed secrets from
  the history. It contains no secret material itself — the values come from a
  git-ignored scripts/secrets-to-purge.txt (template: .example alongside it).
  Rotating the credential at the provider is the only real fix; see the script's
  header and the README's Security section.


-------------------------------------------------------------------------------
 8. VERIFYING AN INSTALL
-------------------------------------------------------------------------------

  Configuration parses (no database needed):
      cd mernapp/backend && node -e "require('./config/env'); console.log('env ok')"

  Frontend builds:
      cd mernapp && npm run build
  A clean build prints "Compiled successfully", or reports only the autoprefixer
  `color-adjust` warning — that one comes from the bootstrap-dark-5 vendor
  stylesheet, not from this project's code.

  Frontend unit tests:
      cd mernapp && npm test

  API responds:
      curl http://localhost:5000/api/health

  Full end-to-end check (REQUIRES a reachable database):
      cd mernapp/backend && npm run seed
      cd mernapp/backend && npm run smoke

  The smoke test boots the real app on a spare port and covers the catalogue,
  signup/login, every authorisation boundary, checkout arithmetic, ETA bounds,
  rider assignment and release, the PDF receipt, live tracking, admin CRUD,
  admin-to-storefront sync and cross-customer isolation. It cleans up the test
  accounts, orders and receipts it creates, and leaves seeded catalogue data
  alone.
